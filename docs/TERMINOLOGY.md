# Terminology

The following vocabulary is mandatory in project documentation.

| Term | Meaning |
|---|---|
| **ED-318 standard** | The published standard itself. |
| **Reference schemas** | The imported machine-readable JSON Schema files used as a canonical technical comparison point. |
| **Reference examples** | Synthetic example and invalid/partial files distributed with the imported schema repository. |
| **National implementation** | A real country's published geographical-zone data and the choices used to represent ED-318 concepts. |
| **National implementation profile** | The project’s documented study of a country's data structure, publisher, lifecycle, distribution, and deviations. |
| **Publishing strategy** | How an authority organizes, versions, distributes, updates, and verifies its datasets. |
| **Source dataset** | A complete file as received from or attributed to a publisher. |
| **Derived sample** | A small project-created subset selected from a source dataset. It is not an unchanged official publication. |
| **Strict schema conformance** | Whether a document validates against a selected reference schema without project tolerance rules. |
| **ED-318-shaped** | Informal project wording for data that visibly carries ED-318 concepts but is not yet demonstrated to be strictly schema-conformant. |
| **Canadian strategy study** | Project research about how a future Canadian implementation might be designed. It is not official Canadian policy. |

## Avoided expressions

Avoid these ambiguous expressions:

- “the official schema”;
- “the example schema”;
- “Spain's schema”;
- “Ireland's schema”;
- “country schema.”

Instead state exactly which artifact is meant: the ED-318 standard, the GitHub reference schemas, a reference example, or a national dataset.
