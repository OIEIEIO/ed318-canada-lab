# ED-318 Reference Notes

## Scope of this document

This file records the laboratory's handling of the uploaded ED-318 schema repository. It is an engineering orientation document, not a substitute for the published EUROCAE standard.

## Imported public schema repository

Upstream project: `https://github.com/eurocontrol-swim/ED-318`

The supplied archive identifies itself as a repository for the ED-318 GeoZones Schema and retains an MIT licence naming Eduard Porosnicu and EUROCONTROL. The archive also acknowledges reuse of portions of the GeoJSON schema.

The archive contains JSON Schema Draft-07 documents for:

- GeoJSON geometries;
- zone authority;
- collection metadata;
- shared data types;
- zone properties;
- zone time periods;
- GeoZone FeatureCollections;
- layered GeoJSON vertical extents.

It also contains complete, partial, extension, and intentionally invalid examples plus a Python validation helper.

## Important limits

Possessing or validating against these public schemas does not establish full ED-318 compliance. Conformance may depend on requirements, semantics, publication rules, profiles, and test criteria that are not represented solely by the JSON Schema files.

The supplied ZIP lacks Git metadata. v0.2.1 therefore does not claim a verified commit SHA. It pins the archive and imported files using SHA-256 checksums in `vendor/ED-318/PROVENANCE.yaml`.

## Repository use

- `schemas/ed-318/` contains unchanged schema JSON files for future validator use.
- `vendor/ED-318/examples/` contains unchanged upstream examples and helper files.
- `vendor/ED-318/LICENSE` retains the upstream MIT licence.
- Project interpretations and tests must be stored outside the imported snapshot.

## Update policy

An upstream update must be imported as a new identified snapshot. Do not overwrite the existing snapshot without changing provenance and reviewing schema, example, licensing, and compatibility differences.
